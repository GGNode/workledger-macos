## 新增检验内容

`test_analysis_semantics.py` 使用明确标注的合成记录与预期响应，覆盖同主题跨会话归并、共享目录不同主题、只有要求、Agent 声称成绩但缺验证、错误恢复与最终阻塞、重复子任务、探测、跨日上下文、未知作者文档、无模型降级、引用和归属强度、长文本尾部、120 个独立任务的分块覆盖、仅部分长记录分析不能算完整覆盖。

`test_analysis_backend.py` 创建临时的假 OpenCode 可执行文件，**实际启动子进程**，验证 `--dir`、cwd、正常 HOME/XDG/内联配置与插件保留、不默认指定模型、临时工具限制、session 提前登记、输出协议、超时终止、不可用/配置/登录错误分类、缓存/刷新/失效、重试上限和总调用预算。它没有登录提供商，没有调用真实 OpenCode，也没有请求真实模型。

`test_analysis_product.py` 验证三种格式共享一个发布版本、失败保留旧报告、渲染失败不替换当前文件、旧版报告迁移、浏览不触发模型、阻塞问题不能被主题归并静默删除、采集错误独立呈现、完整工具输出保留、无调用参数不伪造重试关系、文档截断、慢分析不持有采集锁、202 异步报告与状态一致性。

缓存测试专门覆盖结构归一化后的响应：缓存保存原始经过验证的模型 JSON，再按当前规则重新验证，不能因主题输出丢失 `covered_item_ids` 而每次重新调用模型。

## 人工阅读检查

执行 `scripts/render-analysis-fixture.py` 生成 HTML、Markdown、JSON，并查看桌面和 390px 截图。检查主视图无需打开原始记录便能读出：

- WorkLedger 主题已有局部补丁写入和合成测试依据，真实 Mac 场景仍未验收；一次已经恢复的普通补丁错误不占主页面。
- 谱图检索的得分提升只有 Agent 自述；独立评估因缺少标签而受阻，影响是尚不能确认泛化提升。
- 资源安排只有用户需求，没有预订完成的证据，不被写成成果。
- 实验判断规则是本人明确确认的决定；待确认文档变化仍不归为本人产出。

HTML 和 Markdown 使用同一结果。建议独立标示；原始 Objective、PROBE_OK、失败状态字符串不出现在主叙述。重要陈述均可跳到实际保存的 evidence ID，跳转会自动打开证据折叠区。

**样例使用人工编写的预期 JSON 回放。它用于测试内容组织和错误约束，不用于证明真实模型已经具备这些语义判断。** 回放类只在 tests/ 与演示脚本，生产后端没有固定案例或关键词替换。真实 OpenCode 的任务理解、提供商行为和私有日志质量必须按 `ANALYSIS_UPGRADE.md` 在本机验收。

## 尚未完成的实机验收

当前开发环境没有真实 Mac、OpenCode CLI、用户登录、插件或私有日志。尚未执行真实提供商推理、launchd 下 OpenCode 启动、Finder 自动打开及真实浏览器在线扩展测试。自动化检查不能证明自然语言结论没有错误；引用存在也不能证明推论正确。本机发现错误时应保留脱敏反例、检查原始证据和完整分析链，不应只增加输出字符串断言来“让测试通过”。
